# Contact Collection Tool

## Overview

The RAG system now supports collecting contact information (phone numbers or emails) from users who request callbacks. When a user asks for a callback, the system will:

1. **Detect the request** - The AI recognizes when a user wants to be contacted
2. **Collect contact info** - Asks for phone number or email if not provided
3. **Validate the input** - Checks if the contact information is in a valid format
4. **Save conversation** - Stores the full conversation history in `.cache/history/`
5. **Confirm next steps** - Tells the user they'll be contacted on the next working day

## How It Works

### User Flow

**Example Conversation:**

```
User: "I would like someone to call me about treatment options"
Assistant: "I'd be happy to arrange that. May I have your phone number or email address?"

User: "My number is 07123 456 789"
Assistant: "Thank you for providing your phone number. Someone from the Macular Society will contact you at 07123456789 on the next working day to discuss your query."
```

**Invalid Contact Example:**

```
User: "Please call me on 12345"
Assistant: "Invalid phone number format. The number seems too short. Please provide a valid UK phone number (e.g., 07123456789 or 01234567890)."

User: "Sorry, it's 07123 456 789"
Assistant: "Thank you for providing your phone number. Someone from the Macular Society will contact you at 07123456789 on the next working day to discuss your query."
```

## Features

### 1. Automatic Detection

The AI automatically detects when users request callbacks through natural language:
- "Can someone call me?"
- "I need to speak to someone"
- "Please have someone contact me"
- "I'd like a callback"

### 2. Contact Validation

**Phone Numbers (UK):**
- Accepts UK mobile: `07123456789`, `+447123456789`
- Accepts UK landline: `01234567890`, `02071234567`
- Handles formats: with/without spaces, dashes, parentheses
- Validates length and format

**Email Addresses:**
- Standard format: `user@example.com`
- Auto-converts to lowercase
- Basic format validation

### 3. Conversation History

When contact information is successfully collected, the system saves:

**Location:** `.cache/history/`

**Filename format:** `YYYY-MM-DDTHH-MM-SS_[phone|email]_[value].md`

**Example:** `2026-02-09T20-30-15_phone_07123456789.md`

**Content:**
```markdown
# Conversation History - Callback Request

**Date:** 09/02/2026
**Time:** 20:30:15
**Session ID:** abc123
**Contact Type:** Phone
**Contact Value:** 07123456789

---

## Conversation

### User (20:28:32)

I need help with treatment options

### Assistant (20:28:35)

Based on your macular condition...

### User (20:29:45)

Can someone call me to discuss this further?

### Assistant (20:29:47)

I'd be happy to arrange that. May I have your phone number?

### User (20:30:12)

07123 456 789

---

## Follow-up Required

- [ ] Contact customer at 07123456789
- [ ] Discuss their query
- [ ] Log outcome

*Generated by Macular Society RAG System*
```

## Technical Implementation

### Architecture

```
User Request
    ↓
RAG Service (with OpenAI Function Calling)
    ↓
Tool: collect_contact_information
    ↓
ContactCollectionService
    ├─ validateContact()
    ├─ validatePhoneNumber()
    ├─ validateEmail()
    └─ saveConversationHistory()
```

### Key Files

1. **[contact-collection.service.ts](projects/api/src/modules/contact-collection/contact-collection.service.ts)**
   - Validation logic
   - History saving

2. **[tools.ts](projects/api/src/modules/rag/tools.ts)**
   - OpenAI tool definitions
   - Tool usage instructions

3. **[rag.service.ts](projects/api/src/modules/rag/rag.service.ts)**
   - Tool calling integration
   - Response handling

### API Response

When contact is collected successfully:

```json
{

  "sources": [...],
  "model": "gpt-4o",
  "backend": "openai",
  "contactCollected": {
    "type": "phone",
    "value": "07123456789"
  }

```

## Configuration

No additional configuration required. The system uses existing:
- OpenAI API key (for function calling)
- Model: `gpt-4o` or configured chat model
- Cache directory: `.cache/history/`

## Monitoring

Check collected contacts:
```bash
# List all saved conversations
ls -la .cache/history/

# View a specific conversation
cat .cache/history/2026-02-09T20-30-15_phone_07123456789.md

# Count contacts by type
ls .cache/history/ | grep "_phone_" | wc -l
ls .cache/history/ | grep "_email_" | wc -l
```

## Troubleshooting

**Tool not being called:**
- Check OpenAI API supports function calling (gpt-4o, gpt-3.5-turbo-0613+)
- Verify RAG_TOOLS is imported and used in API call
- Check system prompt includes TOOL_USAGE_INSTRUCTIONS

**Validation always fails:**
- Test validation directly: `service.validateContact('07123456789')`
- Check regex patterns match your region
- Review validation error messages for clues

**History not saved:**
- Verify `.cache/history/` directory exists and is writable
- Check logs for file write errors
- Ensure sufficient disk space
