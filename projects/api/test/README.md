# API Test Suite

## Running Tests

Tests use [Vitest](https://vitest.dev/) and are configured via `vitest.config.ts`.

> ❗❗ Keep in mind that running tests can consume lots of tokens. Avoid running all tests at once if not needed.

### Run all tests

```bash
npm test
```

### Run a specific file

```bash
npm run test -- run test/evals/scenarios/generated/14-generated-become-member.json.test.ts
```

### Run a specific test by name (filter)

Use `-t` to filter by test name — supports partial strings and regex:

```bash
# Match by partial name
npm run test -- run test/evals/scenarios/custom-generated/mental-wellbeing-and-empathy.test.ts -t "isolated caller"

# Match across all files
npm test -- -t "pronoun"
```

### Run a directory of tests

```bash
# All scenario tests
npm run test:scenarios

# Custom-authored scenario tests only
npm run test:scenarios:custom

# RAGAS evaluations
npm run test:ragas

# Everything under test/evals/
npm run test:evals
```

## Test Types

### Unit Tests — `test/unit/`

Standard Vitest tests for pure logic. Fast, deterministic, no external calls.

Examples: query-rewriting regex patterns, contact collection parsing.

```bash
npm test -- run test/unit/
```

---

### LLM-as-Judge Scenario Tests — `test/evals/scenarios/`

Multi-turn conversational evaluations that simulate a real caller interacting with the helpline agent. Each test orchestrates three agents via [@langwatch/scenario](https://github.com/langwatch/langwatch):

- **User agent** — simulates a caller with a specific goal or persona
- **RAG agent** — the actual helpline assistant under test
- **Judge agent** — an LLM that scores each turn against defined criteria

Criteria cover things like medical accuracy, staying in scope, empathy, and safety escalation. Results are saved as JSON for later review.

There are three sub-groups:

- `scenarios/` — hand-authored tests for core helpline topics (AMD, treatments, benefits, adversarial, crisis)
- `scenarios/custom-generated/` — richer scenario tests authored around specific service areas (befriending, counselling, CBS, etc.). These tests are generated by having AI analyze summaries and creating test criteria. Then test code is auto-generated from that.
- `scenarios/generated/` — auto-generated tests produced from topic data files

---

### RAGAS Evaluations — `test/evals/ragas/`

[RAGAS](https://docs.ragas.io/) (Retrieval-Augmented Generation Assessment) is a framework of reference-free metrics for evaluating RAG pipelines. Rather than comparing against a gold answer, it uses LLMs to score properties of the retrieval and generation.

Two metrics are currently measured:

| File | Metric | What it checks |
|------|--------|----------------|
| `01-faithfulness.test.ts` | **Faithfulness** | Whether the answer is grounded in the retrieved source documents (no hallucination) |
| `02-vapi-answer-relevancy.test.ts` | **Answer Relevancy** | Whether the answer actually addresses the question asked |

Each test runs a large dataset (~80 queries) through [LangWatch](https://langwatch.ai/) experiments and records per-query scores. The VAPI test calls the voice assistant API directly; the faithfulness test calls the internal RAG API and also passes along the retrieved context chunks.

---

### VAPI Tests — `test/evals/ragas/02-vapi-answer-relevancy.test.ts`

A specialised evaluation that targets the VAPI voice assistant endpoint rather than the internal RAG API. Because VAPI does not expose retrieved document chunks, only input/output relevancy can be scored. Useful for verifying end-to-end voice pipeline quality independently of the underlying retrieval logic.
